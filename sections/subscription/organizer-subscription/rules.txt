When user come to subscription page its see some data from which user selects its own things and get subscription for that things. We have Premium Modules, Advanced Analytics and Organizations.

First-Time Create / Free-to-Paid Flow

- Build module base:
  - sum(selected non-analytics modules)
- Bundle discount:
  - 2 non-analytics modules => bundleDiscounts[2]
  - 3+ non-analytics modules => bundleDiscounts[3]
  - Applied ONLY to non-analytics module subtotal
- Analytics pricing:
  - Added after bundle discount
  - Analytics gets NO bundle discount

Response:
"bundleDiscounts": {
"twoModules": 10,
"threeModules": 15,
"\_id": "69a8099ad645cabb2231cee6"
},

After that calculation we get an base price for organization.
Now we have discount percentage on organization selection we need to calculate the base price and add discount based on the number of organization user select.

Response:
"multiOrgPricing": {
"oneOrg": 100,
"twoOrgs": 95,
"threeOrgs": 90,
"fourOrgs": 85,
"fiveOrgs": 80,
"sixPlusOrgs": 75,
"\_id": "69a8099ad645cabb2231cee7"
},

Then user can select monthly and yearly

- Yearly pricing:
- yearlyBase = totalMultiOrgPrice \* 12
- yearlyDiscount applied on yearlyBase
- finalYearly = yearlyBase - yearlyDiscountAmount
- Final amount sent:
  - monthly => totalMultiOrgPrice
  - yearly => finalYearly

Response:
"yearlyDiscount": {
"discountPercent": 25,
"\_id": "69a8099ad645cabb2231cee8"
},

Downgrade to Free Rule (This will apply in next cycle)

- Triggered when selection becomes empty (no module + no analytics).
- Payload is force-normalized to:
  - subscriptionTypes: ["free"]
  - pricingPlan: "monthly"
  - numberOfOrganizations: 1
  - totalSubscriptionAmount: 0

  API Update Payload Contract

- PUT /organizer/subscriptions
- Body fields:
  - subscriptionTypes: string[]
  - pricingPlan: "monthly" | "yearly"
  - numberOfOrganizations: number
  - totalSubscriptionAmount: number

Update Flow Change Detection:

- Change analysis should run for paid users.
- Change types:
  - upgrade
  - downgrade
  - no_change
  - free_plan
- Only pure additions are treated as upgrade in current logic.
- If user downgrade something then it consider in next recurring there is nothing as refund in this project.
